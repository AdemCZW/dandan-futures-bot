# 定時跑（Railway cron）部署指南

把交易 bot 從「24 小時常駐容器」改成「每小時醒一次、跑完就退出」，省下常駐成本，
又不用一直開電腦。2026-07-14 建立。

## 為什麼可行、為什麼安全

- **4h 策略不需要常駐**：每 4 小時才有一根新 K 棒，只要在收盤後醒來檢查一次即可。
- **出場由交易所守護**：進場後掛 `STOP_MARKET` / `TAKE_PROFIT_MARKET` 條件單在幣安端，
  bot 離線期間仍會自動停損/停利（`core/futures_execution_engineer.py`）。
- **不會重複進場（防 F2）**：`run_once.py` 每次啟動 →
  1. `trader.restore()` 以交易所實際持倉為準重建倉位；
  2. `restored_last_bar()` 讀 state 檔 `last_decision.ts` 判斷「這根 K 棒是否已決策過」，
     同一根只刷心跳、不重複決策；state 檔遺失時退回交易日誌(Postgres)推斷。
- **持久化兩條路都在 Railway、都持久**：
  - state 檔（熔斷器/精確 SL·TP/scale-out/last_decision）→ **磁碟卷**（`BOT_STATE_DIR`）；
  - 交易日誌 → **Postgres**（`DATABASE_URL`，你現有那顆）。

單輪邏輯逐位元對齊常駐版 `run_multi_futures.poll_loop` 的迴圈本體，只是「跑一次就退出」。

## 前置

- `run_once.py`（一次性進入點）、`tests/test_run_once.py`（6 個測試，全綠）已在 repo 根目錄。
- 沿用同一個 Docker image（`Dockerfile`）與同一份 `BOTS_CONFIG`。

## Railway 面板設定步驟（重用現有 `dandan-futures-bot` 服務）

1. **加磁碟卷（Volume）**：服務 → Volumes → 新增，掛載點填 `/data`（1GB 足夠）。
2. **環境變數**（Variables）：
   - `BOT_STATE_DIR=/data` ← state 檔寫進磁碟卷，跨執行保留（**關鍵**）
   - `BOTS_CONFIG=[...]` ← 你的 bot 陣列（smc 8 幣 + vol_momentum，見研究日誌 2026-07-13）
   - `BINANCE_FUTURES_TESTNET_KEY` / `BINANCE_FUTURES_TESTNET_SECRET` ← 測試網金鑰
   - `DATABASE_URL` ← 你現有 Postgres（交易日誌 + F2 後備）
   - `SIGNAL_DATA_SOURCE=mainnet`（訊號用主網公開 K 線，與回測同源）
3. **啟動指令**：Settings → Deploy → Start Command 改成
   `python -u run_once.py`
4. **排程（Cron Schedule）**：Settings → 填 cron 字串：
   - **建議：`2 * * * *`**（每整點 +2 分跑一次）— 4h 收盤那次才決策，其餘只跑軟停損後備，
     成本仍極低，且每小時對帳一次、較穩。
   - **最省：`2 0,4,8,12,16,20 * * *`**（只在 4h 收盤後跑，一天 6 次）。
5. **重啟策略**：設為 **不自動重啟**（cron 一次性，退出即完成；下次由排程再觸發）。
   移除 healthcheck（run_once 不起 HTTP、跑完就退）。

> 也可直接把 `railway.cron.json` 的內容套用（或把服務的 config-as-code 路徑指向它），
> 但**磁碟卷與環境變數仍必須在面板設定**，無法只靠 json。

## 排程頻率的取捨（誠實說明）

- 交易所端條件單是**即時**的 → 停損/停利不受排程頻率影響，一律即時觸發。
- `run_once` 每次會跑一次「軟停損後備」（給 testnet 條件單偶發故障用）。跑越密，這層後備
  越即時：`2 * * * *`（每小時）比 `每4h` 多 4 倍的後備頻率，成本差異仍很小。
- 錯過的排程（Railway 維護等）只會跳過那一根 K 棒 → 4h 策略可接受，不會重複或錯亂。

## 本機驗證（不下單）

```bash
.venv/bin/python -m pytest tests/test_run_once.py -q   # 驗證單輪/去重/失敗隔離邏輯
```

> ⚠️ 直接 `python run_once.py`（帶真金鑰）**會對測試網下單**。要驗證「會不會下單」請跑上面
> 的測試；真正上線的啟動請你本人在 Railway 執行。

## 回滾

把 Start Command 改回 `python -u run_multi_futures.py`（或 `python -u run_live_futures.py`）、
移除 Cron Schedule，即回到常駐模式。程式碼與 state 檔格式完全相容，不需其他變更。
